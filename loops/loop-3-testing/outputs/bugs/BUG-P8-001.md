## Steps to reproduce   (exact curl / Playwright steps)
1. Seed 1,000 tasks: `bash loops/loop-3-testing/outputs/curl/phase-8-perf.sh seed` (titles `PERF8T <i> alpha|beta`, status/priority cycling, due dates −30..+59 days; 1,010 tasks in total).
2. API is fast: `curl -s -o /dev/null -w '%{http_code} %{time_total}' 'http://localhost:8080/api/tasks?q=PERF8T%20555&archived=false&sort=CREATED_AT&direction=DESC'` → `200 0.003`; every list/search/filter call measured 1–33 ms (see `outputs/curl/phase-8-perf.out` P-01..P-11 and the browser resource timings below).
3. Playwright MCP `browser_run_code_unsafe`, viewport 1440×900:
   - `page.goto('http://localhost:4200/tasks')`, wait until 1,010 `app-task-item` rows are rendered, wait 1 s.
   - Register a `PerformanceObserver({type:'longtask'})`.
   - `t0 = Date.now()`; `page.getByRole('searchbox', {name: 'Search tasks by title'}).fill('PERF8T 555')`
   - `page.waitForFunction(() => document.querySelectorAll('app-task-item').length === 1)`; `ms = Date.now() - t0`.
   - Repeat with `page.locator('#filter-status').selectOption('TODO')` (→ 338 rows), `selectOption('')` (→ 1,010), `page.locator('#filter-priority').selectOption('HIGH')` (→ 337), clearing the search (→ 1,010).
4. Repeat step 3 with `page.emulateMedia({reducedMotion: 'reduce'})`.

## Suspected area
`frontend/src/app/features/tasks/tasks-page.component.ts`: rendering/removing rows of the `@for (task of store.tasks(); track task.id)` list with `animate.enter="task-enter"` / `animate.leave="task-leave"` on every `app-task-item`, and the FLIP `afterRenderEffect` (reads `offsetTop` of every row and starts an `el.animate()` per moved row). Also check per-row cost in `task-item.component.ts` (e.g. `animate.enter` on the overdue chip, computed values per row) and that the effect does not run repeatedly while leave animations are pending. The app is served by `ng serve` (development mode); the target must still be met there or measured on a production build documented in quickstart.

## Fix (frontend-dev, trial 1)
**Root cause**: every row had `animate.enter` / `animate.leave` classes. Angular runs, per element, a `requestAnimationFrame` that calls `getAnimations()` / `getComputedStyle()` after adding a class, so replacing ~1,000 rows forced ~1,000 style recalculations in a row (seconds of main-thread work, worse with the reduced-motion 0.01 ms durations). The FLIP `afterRenderEffect` also interleaved `offsetTop` reads with `el.animate()` writes (layout thrashing over 1,000 rows), and each row built 3 new `Intl` formatters through `toLocaleString(…, options)`. The overdue chip also used `animate.enter` (another per-row rAF + computed-style read).

**Files changed**
- `frontend/src/app/features/tasks/tasks-page.component.ts`: rows use the callback form `(animate.enter)` / `(animate.leave)`; a `linkedSignal` `animateRows` compares the new list with the previous one and animates only small changes (≤ 20 rows added + removed, not under reduced motion). Bulk updates (search/filter results, first load) are added/removed immediately. FLIP now reads all positions first, then animates, only for small changes and only rows near the viewport.
- `frontend/src/app/features/tasks/task-item.component.ts`: overdue chip uses the plain CSS `qf-pop` class instead of `animate.enter`.
- `frontend/src/app/features/tasks/task-labels.ts`: shared cached `Intl.DateTimeFormat` instances.
- `frontend/src/app/features/tasks/task-toolbar.component.ts`: emptying the search box shows the full list at once (no 200 ms debounce); typing still debounces.
